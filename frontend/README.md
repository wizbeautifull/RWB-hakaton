# Wildberries Mesh · интерфейс

Интерфейс пилота Wildberries Mesh на React, TypeScript и Vite. Инструкция по запуску общего стенда находится в корневом README.

## Запуск

В терминале из этой папки выполните:

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте сайты покупателя `/`, ПВЗ `/pvz/` и продавца `/seller/` на адресе из вывода Vite, обычно `http://localhost:5173`. Для production-сборки выполните `npm.cmd run build`. `npm.cmd run preview` раздаёт все три сайта с тем же прокси.

Vite перенаправляет `/api` на `http://127.0.0.1:8000`. Другой адрес можно задать переменной `MESH_API_TARGET` или через `.env.local`. При развёртывании настройте общий origin для сборки из `dist/` и API. У каждого сайта собственный `index.html`, внутренние маршруты используют hash.

Запустите FastAPI из корня репозитория по его README. При запуске без FastAPI доступны примеры для просмотра. После запуска бэкенда нажмите кнопку состояния подключения в верхней панели.

## Сквозной прогон

1. На сайте ПВЗ зарегистрируйте точки A и B с вместимостью 1000 см³. В A примите партию `lot-1`, товар `CABLE`, продавец `seller-1`, 3 шт. по 100 см³.
2. Откройте сайт покупателя и убедитесь, что кабель появился в каталоге. Выберите B, включите WB Клуб и нажмите «Показать варианты». Выберите доставку в B для прогона прямого рейса или самовывоз из A, если сайт предлагает сборку сегодня. По умолчанию крайний срок для расчёта через 48 часов. Формы даты используют московское время.
3. Скопируйте код получения с сайта покупателя. В очереди ПВЗ А откройте заказ, соберите его и передайте курьеру. Переключите рабочую точку на B, примите и выдайте заказ.
4. Проверьте статус выдачи на сайте покупателя. На сайте продавца введите `seller-1` и проверьте остаток 2 шт. в А. В карточке заказа на сайте ПВЗ видны четыре начисления на 45 ₽. Приёмка партии отражается в начислениях отдельно.
5. В разделе «Для жюри» на сайте ПВЗ сравните расчёты для 8 и 10 заказов и откройте решение по созданному заказу.

## Данные и сценарии

`src/api.ts` содержит типы и вызовы FastAPI. Для повтора идентичного POST после ошибки связи используется тот же `request_id` в текущей сессии страницы. Действия над заказом берутся из `next_actions`. Данные продавца фильтруются по коду продавца и ПВЗ.

Экран жюри рассчитывает контрольную выборку через API. Для изменения загрузки при оформлении реальных заказов измените `demo_routing.trip_orders` в `config/pilot.json` и перезапустите FastAPI. Закрытие окон и сохраняющиеся расходы хаба также настраиваются на сервере. Повторное сканирование с изменённым телом и конкурентные запросы проверяются на уровне API.

Кабинеты загружают прибыль и расходы из API. В оформленном заказе видна доплата за ускорение. По умолчанию она равна 0 ₽.
